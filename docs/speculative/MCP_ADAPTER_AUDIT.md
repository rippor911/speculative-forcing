# MCP Adapter Audit

Branch: `feat/speculative-mcp-adapter`

Baseline assumptions:

- `inference_mcp.py` is the validated always-accept GPU reference.
- The speculative control core semantics must not change.
- This audit does not implement an adapter and does not connect ImageReward.

## Executive Conclusion

The real MCP path is currently embedded in
`SelfForcingTrainingPipeline._inference_with_trajectory_mcp_accelerated`.
That function combines three roles that the controller now separates:

- proposal: denoise the anchor and ask MCP heads for future chunks;
- fallback-shaped target generation: run the target backbone for one block;
- commit: rerun the generator on accepted latent blocks at `context_noise` and
  permanently write Transformer KV.

The adapter boundary can match the existing always-accept output, but only if
proposal and fallback run as temporary transactions. They must restore
Transformer KV content, KV indices, cross-attention cache state, generation
output state, commit-order bookkeeping, and any RNG state they consume before
returning. Permanent KV writes should happen only through the committer, by
reusing the existing context recache logic.

## Confirmed Design Decisions

### Parity

- Temporary transactions must exactly restore every touched K/V slice, all
  per-layer `global_end_index` and `local_end_index` values, RNG state, output
  state, and controller/runtime ordering state.
- Formal GPU acceptance requires equality for `global_end_index`,
  `local_end_index`, visible K/V, latent output, next-anchor behavior, and trace.
- Full allocated K/V equality is diagnostic only. It is useful for debugging
  stray writes, but it is not the formal pass/fail criterion.
- The server run must first execute reference self-repeat. If the reference is
  bitwise deterministic, new-vs-old latent and visible K/V checks require exact
  equality. If the reference self-repeat has nonzero drift, the reference
  self-repeat error becomes the maximum allowed tolerance for new-vs-old checks.

### Schedule

- v1 supports only `ANCHOR_DENOISING_STEPS = [1000]`.
- Any other denoising schedule must fail fast during runtime setup.
- Multi-step diffusion is explicitly out of scope for this adapter stage.

### Fallback

- Fallback uses the rejected candidate's identical `source_noise` object.
- Fallback runs against the current formally committed context.
- The target fallback block is generated by the target backbone one-step at
  timestep `1000`.
- Fallback never starts from the draft latent.
- Fallback restores all temporary state before returning.
- The returned fallback latent is formally recached only by `Committer.commit()`.

### Entrypoint

- `inference_mcp.py` is frozen as the reference oracle.
- The new controller-backed entrypoint is fixed as `inference_speculative.py`.
- The old reference entrypoint must not gain policy parameters.

### Cross-Attention

- `SelfForcingMCPRuntime` provides `prepare()`.
- `prepare()` must complete cross-attention cache initialization before the
  controller runs.
- After `prepare()`, the cross-attention cache is prompt-level read-only state.
- The `prepare()` initialization cost is excluded from the formal rollout
  benchmark.
- If `prepare()` uses a temporary forward, it must use scratch self-attention KV
  and restore RNG state.

### Private Helpers

- The three protocol wrappers must not call pipeline private methods directly.
- Pipeline private methods are wrapped only inside `SelfForcingMCPRuntime`.
- v1 runtime wraps `_mcp_future_chunks`, `_initialize_kv_cache`,
  `_initialize_crossattn_cache`, and `_commit_context_block`.
- v1 must not copy `_commit_context_block` code.
- If parity fails, revisit the smallest public-helper extraction from the
  pipeline.

### Attention Scope

- v1 supports only the actual attention/cache mode produced by
  `configs/ode_init.yaml` in the current validated environment.
- Runtime startup must check the relevant config/model fields.
- Unverified attention/cache modes must fail fast and must not silently degrade
  to a different behavior.
- The local-attention rolling analysis remains documented as future support
  guidance.

### Frame Position

- `current_start` is derived only from `BlockRef.start_frame *
  frame_seq_length`.
- Runtime must not maintain a second independently mutable frame cursor.
- Commit ordering can be tracked by block identity, but frame offsets for
  proposal, fallback, output writes, and recache all come from `BlockRef`.

## Real Call Graphs

### 1. Target Anchor Generation

Reference path:

```text
inference_mcp.main
  -> build_rollout_pipeline
  -> SelfForcingTrainingPipeline.inference_with_trajectory
  -> SelfForcingTrainingPipeline._inference_with_trajectory_mcp_accelerated
  -> for anchor_block in anchor_blocks:
       current_start_frame = block_starts[anchor_block]
       noisy_input = noise[:, current_start_frame:current_start_frame + m]
       timestep = ones([B, m]) * current_timestep
       generator(
         noisy_image_or_video=noisy_input,
         conditional_dict=conditional_dict,
         timestep=timestep,
         kv_cache=kv_cache1,
         crossattn_cache=crossattn_cache,
         current_start=current_start_frame * frame_seq_length,
         mcp_future_noises=mcp_noises if available,
         mcp_future_start_frames=mcp_starts if available
       )
  -> WanDiffusionWrapper.forward
  -> CausalWanModel._forward_inference
  -> CausalWanAttentionBlock.forward, for each layer
  -> CausalWanSelfAttention.forward
```

Inputs:

| Field | Value in the validated MCP inference path |
| --- | --- |
| latent/noise | `noise[:, start:start + m]`, where `m = num_frame_per_block` |
| timestep | `ones([B, m]) * 1000` because `ANCHOR_DENOISING_STEPS = [1000]` |
| current_start | `start_frame * frame_seq_length` |
| cache_start | omitted, so attention uses `cache_start = current_start` |
| conditional | `conditional_dict["prompt_embeds"]` from `WanTextEncoder` |

Returns:

- without MCP futures: `(flow_pred, denoised_pred)`;
- with MCP futures: `(flow_pred, denoised_pred, mcp_flow_preds)`.

State mutation:

- modifies `kv_cache1` for every Transformer layer during the anchor forward;
- each layer writes `k` and `v` slices and fills `global_end_index` and
  `local_end_index`;
- may initialize `crossattn_cache[layer]["is_init"]`, `k`, and `v`;
- may move `generator.model.freqs` to the active device;
- does not write the output latent buffer itself;
- does not update a persistent `current_start` field, because the current
  implementation keeps `current_start_frame` as a local variable.

Adapter requirement:

- `ProposalSource.propose()` may run this call to compute the anchor latent, but
  must restore all temporary KV and cross-attention mutations before returning.
  It returns the anchor as `CommitRequest(source="anchor")`; permanent recache is
  delayed until `Committer.commit()`.

### 2. MCP Future Chunks Generation

Reference path:

```text
SelfForcingTrainingPipeline._inference_with_trajectory_mcp_accelerated
  -> _mcp_future_chunks(anchor_block, block_starts, all_num_frames, noise, 0)
  -> WanDiffusionWrapper.forward(..., mcp_future_noises, mcp_future_start_frames)
  -> CausalWanModel._forward_inference(..., return_features=mcp_tap_layers,
                                      mcp_patch_inputs=...)
  -> CausalWanModel._embed_mcp_chunks
  -> WanDiffusionWrapper._run_mcp
  -> MCPStack.forward
  -> MCPModule.forward, chained by depth
  -> MCPBlock.forward
  -> MCPSelfAttention.forward
  -> CausalHead + mcp_unpatchify
```

Inputs:

| Field | Value |
| --- | --- |
| future source noise | `noise[:, lo:hi]` for block `anchor_block + 1 + k` |
| future start frame | `block_starts[anchor_block + 1 + k]` |
| future timestep | default `MCP_INPUT_TIMESTEP = 1000` when `mcp_timesteps is None` |
| upstream features | tapped backbone features from `mcp_tap_layers` |

Returns:

- `_mcp_future_chunks()` returns `(noises, starts)`, with `None` entries for
  invalid future chunks;
- `_run_mcp()` returns `mcp_flow_preds`, each shaped `[B, F, C, H, W]`;
- the rollout converts each deployed draft with `draft = mcp_noises[k] -
  flow_pred`.

State mutation:

- `_mcp_future_chunks()` itself is pure except for creating lists and borrowing
  views into `noise`;
- MCP heads do not directly modify `kv_cache`;
- the backbone forward that supplies tapped features does modify `kv_cache1` and
  may initialize `crossattn_cache`;
- MCP module state is parameter-only during inference; no persistent MCP runtime
  generation state is updated.

Adapter requirement:

- `ProposalSource.propose()` should call `_mcp_future_chunks()` first, then run
  the same generator call with `mcp_future_noises` and
  `mcp_future_start_frames`.
- It should emit only drafts whose MCP flow predictions were returned and whose
  depth is `<= request.max_depth`.
- Each `DraftCandidate.source_noise` must be the exact noise object used to make
  the draft, so fallback can regenerate the target block from the same source.

### 3. Target Fallback Block Generation

There is no dedicated fallback path in `inference_mcp.py`, because the reference
policy is always-accept. The real target-generation call to reuse is the same
backbone denoise call used for an anchor block, but without MCP future inputs.

Fallback-shaped path:

```text
SpeculativeController
  -> FallbackGenerator.generate(rejected_candidate)
  -> generator(
       noisy_image_or_video=rejected_candidate.source_noise,
       conditional_dict=conditional_dict,
       timestep=ones([B, F]) * 1000,
       kv_cache=kv_cache1,
       crossattn_cache=crossattn_cache,
       current_start=rejected.block.start_frame * frame_seq_length
     )
  -> WanDiffusionWrapper.forward
  -> CausalWanModel._forward_inference
  -> CausalWanSelfAttention.forward
```

Inputs:

| Field | Value |
| --- | --- |
| source noise | `candidate.source_noise` |
| timestep | `ones([B, candidate.block.num_frames]) * 1000` |
| current_start | `candidate.block.start_frame * frame_seq_length` |
| MCP futures | omitted |

Returns:

- `FallbackResult(block=candidate.block, latent=denoised_pred,
  source_noise=candidate.source_noise)`.

State mutation:

- the generator call temporarily writes `kv_cache1` and may initialize
  `crossattn_cache`;
- it must not write the output latent buffer;
- it must not advance permanent commit-order state;
- it must not call the context recache commit path.

Adapter requirement:

- fallback runs after the controller has committed the accepted prefix, so its
  input KV is the permanent KV for the prefix immediately preceding the rejected
  block;
- all fallback generator mutations must be restored before `generate()` returns;
- the returned `source_noise` must preserve object identity with
  `candidate.source_noise`, matching the controller invariant.

### 4. Permanent Latent/Context Block Commit To Transformer KV

Reference path:

```text
SelfForcingTrainingPipeline._inference_with_trajectory_mcp_accelerated
  -> output[:, start:start + m] = latent
  -> commit_to_cache(latent, start_frame)
       context_timestep = ones([B, m]) * context_noise
       context_latent = scheduler.add_noise(
         latent.flatten(0, 1),
         torch.randn_like(latent.flatten(0, 1)),
         context_timestep.flatten(0, 1)
       ).unflatten(...)
       generator(
         noisy_image_or_video=context_latent,
         conditional_dict=conditional_dict,
         timestep=context_timestep,
         kv_cache=kv_cache1,
         crossattn_cache=crossattn_cache,
         current_start=start_frame * frame_seq_length
       )
  -> WanDiffusionWrapper.forward
  -> CausalWanModel._forward_inference
  -> CausalWanSelfAttention.forward
```

Inputs:

| Field | Value |
| --- | --- |
| latent | accepted anchor, accepted draft, or fallback target latent |
| context timestep | `ones([B, num_frames]) * pipeline.context_noise` |
| context noise | `torch.randn_like(latent.flatten(0, 1))` |
| current_start | `start_frame * frame_seq_length` |
| cache_start | omitted in the local closure; `_commit_context_block()` passes `cache_start=self._cache_start()` |

Returns:

- generator output is ignored; the side effect is the permanent KV update.

State mutation:

- writes the output latent buffer for the committed block;
- writes `kv_cache1[layer]["k"]` and `["v"]` for every layer;
- advances `global_end_index` and `local_end_index` for every layer;
- may initialize or reuse `crossattn_cache`;
- consumes CUDA RNG through `torch.randn_like`;
- records the block as formally committed, without maintaining an independent
  frame cursor.

Adapter requirement:

- `Committer.commit()` should be the only code path that calls this context
  recache permanently.
- It should reuse `SelfForcingTrainingPipeline._commit_context_block()` as the
  closest existing implementation, plus the output-buffer write and
  commit-order bookkeeping that the helper does not perform.
- For equivalence with the reference MCP path, `start_frame` must equal the
  current cache start when committing in order. Then `_commit_context_block()`'s
  `cache_start=self._cache_start()` is equivalent to the local closure that omits
  `cache_start`.

## Attention KV Mutation Details

In `CausalWanSelfAttention.forward`, the KV-cache branch computes:

```text
current_start_frame = current_start // frame_seqlen
roped_query = causal_rope_apply(q, ..., start_frame=current_start_frame)
roped_key   = causal_rope_apply(k, ..., start_frame=current_start_frame)
cache_end   = cache_start + roped_query.shape[1]
```

Then it writes to the cache before running attention:

```text
kv_cache["k"][:, local_start_index:local_end_index] = roped_key
kv_cache["v"][:, local_start_index:local_end_index] = v
x = attention(
  roped_query,
  kv_cache["k"][:, max(0, local_end_index - max_attention_size):local_end_index],
  kv_cache["v"][:, max(0, local_end_index - max_attention_size):local_end_index]
)
kv_cache["global_end_index"].fill_(cache_end)
kv_cache["local_end_index"].fill_(local_end_index)
```

If local attention is enabled and the cache is full, it first rolls visible cache
content left:

```text
kv_cache["k"][:, sink_tokens:sink_tokens + num_rolled_tokens] =
  kv_cache["k"][:, sink_tokens + num_evicted_tokens:
                   sink_tokens + num_evicted_tokens + num_rolled_tokens].clone()
kv_cache["v"][:, sink_tokens:sink_tokens + num_rolled_tokens] = ...
```

Conclusion: restoring only `global_end_index` and `local_end_index` is not a
sufficient adapter transaction rule.

- In the narrow global-attention append case, index restore hides the appended
  temporary block from later attention, but the KV tensors are still changed.
- In overwrite-style calls, stale temporary K/V can remain inside the restored
  visible prefix.
- In local-attention roll calls, committed historical K/V slices are physically
  shifted before the new block is written; index restore cannot reconstruct them.

Minimum rollback data per temporary generator forward:

| Case | K/V slices that must be restored for every layer |
| --- | --- |
| Direct write, no roll | `k` and `v` for `[local_start_index:local_end_index]` |
| Direct append, strict no-mutation rollback | same written slice `[local_start_index:local_end_index]` |
| Local-attention roll | `k` and `v` for `[sink_tokens:local_end_index_after_roll]` |
| Conservative fallback | clone the layer's visible K/V window before the forward and restore it |

The adapter should prefer strict no-mutation rollback, because the GPU
acceptance target asks for latent and KV equality, not just future-output
equivalence.

## State Ownership Table

| State | Current owner | Mutated by current code | Adapter owner |
| --- | --- | --- | --- |
| `kv_cache1[layer]["k"]` | `SelfForcingTrainingPipeline` | every generator forward with `kv_cache` | `Committer` permanently; proposal/fallback temporarily with rollback |
| `kv_cache1[layer]["v"]` | `SelfForcingTrainingPipeline` | every generator forward with `kv_cache` | same as K |
| `global_end_index` | per-layer KV dict | every KV forward fills it with `cache_end` | `Committer` permanently; temporary adapters restore |
| `local_end_index` | per-layer KV dict | every KV forward fills it with computed local end | `Committer` permanently; temporary adapters restore |
| `crossattn_cache[layer]["is_init"]` | pipeline cross-attn cache | first T2V cross-attn forward sets it true | runtime/committer permanently; temporary adapters restore |
| `crossattn_cache[layer]["k"]`, `["v"]` | pipeline cross-attn cache | first cross-attn forward replaces zero tensors with prompt K/V tensors | runtime/committer permanently; temporary adapters restore |
| `current_start_frame` | local variable in rollout | advanced by loop structure, not stored on pipeline | derived from `BlockRef.start_frame`; no independent runtime frame cursor |
| output latent buffer | local `output` tensor | written before `commit_to_cache()` in reference | `Committer.commit()` writes committed blocks at `BlockRef.start_frame` |
| full source `noise` | rollout input | read-only after creation | runtime read-only source buffer |
| MCP future noise views | local proposal lists | `_mcp_future_chunks()` creates borrowed views | proposal temporary payload; preserved as `source_noise` |
| MCP future start frames | local proposal lists | `_mcp_future_chunks()` creates list values | proposal metadata/block refs |
| `mcp_flow_preds` | local proposal result | generated by `_run_mcp()` | proposal temporary result |
| `block_starts`, `all_num_frames`, `anchor_blocks` | local rollout plan | created once per rollout | runtime immutable plan used to build `BlockRef` values |
| `exit_flags` | local rollout schedule | `generate_and_sync_list()` creates once and consumes RNG | runtime schedule; must be generated in the same order as reference |
| scheduler `sigmas`, `timesteps` device | `FlowMatchScheduler` | `add_noise()` and conversion helpers move tensors to active device | runtime shared object; device moves are acceptable but should be deterministic |
| `generator.model.freqs` | `CausalWanModel` | `_forward_inference()` moves it to model device if needed | runtime shared model state; initialize consistently before comparison |
| `generator.model.block_mask` | `CausalWanModel` | train path lazily caches masks; inference KV path does not build it | avoid train path in adapter proposal/fallback/commit |
| CUDA RNG | PyTorch runtime | `generate_and_sync_list()` and commit `torch.randn_like()` consume it | runtime; proposal/fallback must not shift permanent commit RNG |
| CPU RNG / Python RNG / NumPy RNG | process globals | seeded by `inference_mcp.py`; source noise uses a separate CPU generator | preserve setup sequence for equivalence |
| VAE cached decode state | VAE internals | not used in reference, `use_cache=False` | outside adapter scope |

## Proposal, Fallback, Commit Timing

Always-accept window:

```text
controller.run(anchor_block=i)
  proposer.propose(i)
    snapshot temporary mutable state
    run anchor forward with MCP futures
    build anchor CommitRequest
    build draft candidates from mcp_noises[k] - mcp_flow_preds[k]
    restore temporary mutable state
    return ProposalBatch

  committer.begin()
  committer.commit(anchor)
    output[start:start + F] = anchor.latent
    _commit_context_block(anchor.latent, start)

  for each draft:
    evaluator.evaluate(draft)
    policy.decide(...) -> accept
    committer.commit(draft)
      output[draft_start:draft_start + F] = draft.latent
      _commit_context_block(draft.latent, draft_start)

  committer.complete()
```

First-reject window:

```text
controller.run(anchor_block=i)
  proposer.propose(i) -> anchor + drafts, with temporary state restored

  committer.begin()
  committer.commit(anchor)

  accepted prefix drafts:
    evaluate -> accept
    committer.commit(draft)

  rejected draft:
    evaluate -> reject
    mark deeper drafts invalid
    fallback.generate(rejected)
      snapshot temporary mutable state
      run target backbone on rejected.source_noise
      restore temporary mutable state
      return FallbackResult
    committer.commit(fallback)

  committer.complete()
```

Rollback on exception:

```text
committer.begin()
  snapshot permanent transaction state:
    KV indices
    K/V slices or visible windows that may be modified by commits
    crossattn cache state
    output slices for blocks in this transaction
    commit-order bookkeeping
    RNG state if commit has consumed random context noise

any later error
  -> committer.rollback()
       restore all transaction state
```

## Adapter Interface Answers

### 1. How `ProposalSource.propose()` should generate anchor and MCP drafts

It should reproduce the proposal half of
`_inference_with_trajectory_mcp_accelerated`:

1. Require `request.anchor_block.start_frame` and `.num_frames`, then derive
   `current_start = request.anchor_block.start_frame * frame_seq_length`.
2. Slice the anchor input from the immutable source noise.
3. Build future source chunks with `_mcp_future_chunks()`.
4. Run `generator.forward()` once with the anchor input, `kv_cache1`,
   `crossattn_cache`, `current_start`, and MCP futures.
5. Use `denoised_pred` as the anchor latent.
6. Convert each deployed MCP flow with `draft = source_noise - flow_pred`.
7. Return `ProposalBatch(anchor=CommitRequest(...), drafts=(...))`.

Before returning, it must restore all KV indices, all K/V slices touched by the
temporary generator forward, cross-attention cache state, output state,
commit-order bookkeeping if touched, and RNG state if the proposal path consumed
RNG. In the validated `inference_mcp.py` path, proposal uses one denoising step
at 1000 and should not consume random noise during denoising.

### 2. How `FallbackGenerator.generate()` should use `candidate.source_noise`

It should run the target backbone on exactly `candidate.source_noise`, not on a
newly sampled tensor and not on the draft latent:

```text
noisy_input = candidate.source_noise
timestep = ones([B, candidate.block.num_frames]) * 1000
current_start = candidate.block.start_frame * frame_seq_length
generator(..., noisy_input, timestep, kv_cache1, crossattn_cache, current_start)
```

It returns `FallbackResult` with the same `BlockRef`, the target
`denoised_pred`, and the identical `source_noise` object. It must restore all
temporary state before returning and must not call `_commit_context_block()`.

### 3. What existing logic `Committer.commit()` should reuse

It should reuse `SelfForcingTrainingPipeline._commit_context_block()` for the
permanent Transformer KV write. That helper already implements the reference
context recache pattern:

- build `context_timestep`;
- add scheduler context noise to the accepted latent;
- run the generator with `kv_cache1`, `crossattn_cache`, `current_start`, and
  `cache_start=self._cache_start()`.

The committer must add the missing responsibilities around that helper:

- write the committed latent into the output buffer;
- update commit-order bookkeeping after successful commit;
- snapshot/restore permanent transaction state for controller rollback.

`current_start` for this helper is always derived from
`request.block.start_frame * frame_seq_length`; the runtime must not keep a
second independently mutable frame cursor.

### 4. Whether restoring only global/local indices is enough

No. It is insufficient for the real attention implementation.

`CausalWanSelfAttention.forward()` writes K/V tensor slices before it updates
the indices. With local attention, it may also roll older visible K/V content
left before writing the new block. Restoring only `global_end_index` and
`local_end_index` can hide an appended block from attention in one narrow case,
but it cannot provide strict no-mutation semantics and cannot repair local
rolling or visible overwrites.

At minimum, the adapter needs per-layer restore data for the K/V slices written
by every temporary forward. When the local rolling branch runs, it must restore
the rolled range as well, practically `[sink_tokens:local_end_index_after_roll]`
for both `k` and `v`.

### 5. How private helpers are used

The three protocol wrappers must not call pipeline private methods directly.
Private pipeline calls are centralized behind `SelfForcingMCPRuntime` so state
ownership and future extraction remain reviewable.

`_mcp_future_chunks`:

- v1 runtime wraps it because it is the exact helper that preserves future
  noise/start-frame semantics;
- wrappers receive only runtime-produced proposal payloads.

`_commit_context_block`:

- v1 runtime wraps it as the source of truth for permanent context recache;
- v1 must not copy this helper's code into a new implementation.

`_initialize_kv_cache` and `_initialize_crossattn_cache`:

- v1 runtime wraps both helpers to allocate exactly the currently validated KV
  and cross-attention cache shapes and dtypes.

No extraction is implemented in this audit. If parity fails, revisit a minimal
public helper extraction from `SelfForcingTrainingPipeline`.

### 6. One adapter object or shared runtime plus three wrappers

Use one shared MCP runtime plus three thin wrappers:

- `MCPProposalSource(runtime)`;
- `MCPFallbackGenerator(runtime)`;
- `MCPCommitter(runtime)`.

The runtime should own the generator, scheduler, conditional dict, immutable
source noise, rollout plan, KV/cross-attn caches, output buffer, commit-order
bookkeeping, and snapshot utilities. The wrappers should expose only the
protocol method they need.

This keeps state ownership readable: proposal and fallback can borrow the
runtime only through temporary transactions, while the committer is visibly the
only permanent writer. A single object implementing all three protocols would
make it easier to accidentally call commit-only helpers from proposal/fallback
and would blur the audit boundary the control core was designed to enforce.

### 7. How to guarantee always-accept equality with `inference_mcp.py`

The controller path should be compared against `inference_mcp.py` under these
conditions:

1. Same checkpoint, config, prompt, device, dtype, `mcp_depth`, `num_frames`, and
   `seed`.
2. Same `make_noise()` behavior, including its separate CPU generator.
3. Same seed reset immediately before rollout.
4. Same pipeline construction, including `ANCHOR_DENOISING_STEPS = [1000]`,
   `context_noise = 0`, `mcp_num_modules = mcp_depth`, and
   `mcp_accel_depths = mcp_depth`.
5. Same rollout plan: `period = mcp_depth + 1`, same `anchor_blocks`, same
   `block_starts`, same `all_num_frames`.
6. Same call to `generate_and_sync_list(len(anchor_blocks), 1, device)` before
   window execution, even though the result is all zero, because it may consume
   CUDA RNG and shift later context-noise draws.
7. Proposal uses the same anchor+MCP generator forward and restores temporary
   mutations before returning.
8. Always-accept policy commits anchor then all drafts in the same order as the
   reference loop.
9. Commit uses `_commit_context_block()` and therefore consumes
   `torch.randn_like()` in the same per-block order as the reference.
10. Final comparison checks both latent output and every layer's KV state:
    `global_end_index`, `local_end_index`, and K/V content in the visible cache
    window. Full allocated K/V comparison is diagnostic only.

## Recommended Adapter Structure

Expected shape, not implemented in this audit:

```text
speculative/adapters/runtime_state.py
  RuntimeStateSnapshot helpers
  KV slice/index/RNG/output snapshot and restore primitives

speculative/adapters/self_forcing_runtime.py
  SelfForcingMCPRuntime
    - owns model/pipeline references
    - builds immutable rollout plan and BlockRef values
    - initializes KV and cross-attn caches via prepare()

speculative/adapters/self_forcing_mcp.py
```

The important constraint is that runtime owns state and wrappers own protocol

## Risk List

| Risk | Why it matters | Mitigation |
| --- | --- | --- |
| Proposal leaves K/V bytes behind | Breaks no-permanent-mutation contract and KV equality | restore written K/V slices, not only indices |
| Local-attention cache rolling | Physically shifts old visible K/V | snapshot/restore rolled range |
| Cross-attn cache initialized during proposal | First proposal mutates persistent prompt K/V cache | initialize prompt-level cross-attn cache in `prepare()` before controller windows |
| RNG drift | Context recache uses `torch.randn_like`; schedule generation may consume RNG | match reference seed/reset and schedule calls; restore temp RNG if consumed |
| FSDP parameter visibility | MCP must run inside wrapper forward | keep MCP invocation inside `WanDiffusionWrapper.forward()` |
| `source_noise` identity loss | Controller validates fallback source identity | drafts must store the exact borrowed future noise object |
| Output write before failed commit | Rollback must restore output buffer | committer transaction snapshots output slices |
| Private helper coupling | Helpers are private and pipeline-specific | wrappers call only runtime methods; runtime wraps allowed private helpers |
| Multi-step denoising extension | Proposal/fallback could consume RNG and diverge from reference | v1 fails fast unless schedule is `[1000]` |
| VAE cache | Cached decode has no rollback semantics | keep VAE outside controller and use `use_cache=False` |
